# Anti-cheat and limitations

## What the MVP prevents
- a random/non-enrolled credential cannot check into another course
- check-in is rejected unless the lecturer has opened the session
- QR content is signed; changing student ID invalidates the signature
- duplicate scans update the same unique attendance row instead of creating duplicates
- badges are computed by backend data and cannot be created from the UI

## What the Wallet QR MVP does not fully prevent
A student can photograph/share a static Wallet QR credential. A production system should add one or more of:
- Apple-approved NFC Student ID / NFC pass redemption
- short-lived rotating QR generated by the native app
- device binding / App Attest
- lecturer terminal displays student name/photo for visual confirmation
- proximity validation only with a carefully justified privacy design

This limitation should be discussed openly in the thesis. It is an architectural reason to keep `AttendanceRecord` independent of the credential transport mechanism.
